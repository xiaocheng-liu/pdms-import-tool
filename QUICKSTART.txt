PDMS 数据导入工具 1.0 —— 实施部署与使用说明（快速版）
========================================================================

一、运行环境
  1. 目标机器需安装 JDK 11 或更高版本（推荐 17 / 21）
     验证：命令行执行 java -version，能显示版本号即正常
     未安装时请先安装 JDK，或设置环境变量 JAVA_HOME 指向 JDK 目录
     机器上没有 JAVA_HOME、PATH 里也没有 java 时，可在本目录 jdk-path.txt 中填写 JDK 安装目录
  2. 机器需能通过网络访问目标数据库（Oracle / PostgreSQL / 达梦 / 人大金仓 KingbaseES / MySQL）
  3. 无需安装 Maven、无需联网（三种数据库驱动已打进 jar 内）

二、启动
  Windows   ：双击 run.bat（会弹出一个命令行窗口，导入过程中请勿关闭）
             指定 JDK：run.bat "C:\Program Files\Java\jdk-17"
  macOS/Linux：终端执行 ./run.sh；指定 JDK：./run.sh /opt/jdk-17
  手动启动  ：java -Dfile.encoding=UTF-8 -Xmx1g -jar pdms-import-tool.jar

  指定 JDK 的三类方式（优先级从高到低）：
     1) 命令行参数：run.bat <JDK目录>    /   ./run.sh <JDK目录>
     2) 环境变量  ：PDMS_JAVA_HOME=<JDK目录>
     3) 配置文件  ：编辑本目录 jdk-path.txt，写一行 JDK 安装目录（推荐给实施人员）
  前三种为显式指定，路径无效（目录下没有 bin/java）时直接报错；
  都没指定时才回退到 JAVA_HOME / PATH 里的 java

三、使用步骤
  1. 数据库连接：选择类型（Oracle / PostgreSQL / 达梦 / 人大金仓 KingbaseES），
     填写主机、端口、服务名（或库名）、用户名、密码、Schema（默认 KBE），点“测试连接”
     - Oracle：填服务名；若使用 SID，服务名处填 SID:实例名
     - PostgreSQL / 达梦 / 人大金仓：填数据库名
     - 人大金仓默认端口 54321，按 PG 兼容模式处理（表名/列名转小写）
     - MySQL 默认端口 3306，表名/列名转小写；库即 schema，Schema 一栏留空（已置灰）
  2. 数据源文件夹：点“选择文件夹”选中 CSV 所在目录（如 E:\oracleToCSV\kbe），
     再点“扫描 CSV”。文件名即表名（rule_dosage.csv → 表 RULE_DOSAGE）
  3. 在表清单中勾选要导入的表（默认全选，可全选/反选，支持按大小排序）
  4. 设置导入选项（首次建议按下表取值）
       并发线程数       6      同时决定最大数据库连接数
       批量提交行数     5000   数据量大可加大到 10000
       大表分片阈值     200MB  超过则拆成多个分片并行导入
       单表最大分片数   8      实际分片数 = min(并发线程数, 该值)
       写入超时秒数     120    单批执行/提交超过该秒数无进展则自动取消；填 0 关闭
       CSV 编码         UTF-8  出现中文乱码时改为 GBK
       导入前清表       不清空 需要重置数据时选 TRUNCATE（会二次确认）
       极速模式         按需   数据量大时勾选：PG 走 COPY，Oracle/达梦走 APPEND
       空字符串转 NULL  勾选
       失败跳过继续     勾选   个别坏行不会中断整表
  5. 点“开始导入”，观察表格进度与下方日志
  6. 结束后若存在失败行，日志区会给出失败明细文件路径（默认
     ~/.pdms-import-tool/logs/failures_时间戳.tsv），也可点“导出失败明细”另存

四、失败行怎么处理
  失败明细字段：表名、行号、错误码、错误信息、原始数据（一行 CSV，可直接修复后重放）
  常见原因与处理：
    1) 主键/唯一键冲突 → 目标表已有相同数据：改为清表后导入，或先清理目标数据
    2) 字段超长（如 ORA-12899、22001）→ 目标表列长度小于数据长度：扩列或截断数据
    3) 非空约束 → 源数据该列为空：补数据或允许列为空
    4) 值非法（如“列 CREATE_TIME 的值「xxx」不是合法日期时间”）→ 修正该行的日期/数字格式
  修复方法：把失败明细的“原始数据”列整理成 CSV（需含表头，文件名与表名一致），
  放到单独目录，只导入该目录即可补齐数据

五、配置文件位置
  Windows ：C:\Users\当前用户\.pdms-import-tool\config.properties
  macOS   ：~/.pdms-import-tool/config.properties
  内容包含连接信息与导入选项（密码为明文保存，仅限本机自用）

六、导入慢 / 进度不动时怎么判断
  程序会把耗时拆开打印到日志区，据此可快速定位：
    1) 表格里的“成功行 / 失败行”是实时更新的（每 2000 行刷新一次），可直接看是否在推进
    2) 若 10 秒以上无进展，日志区会自动输出一条看门狗信息，例如：
       [等待] kb_document[分片1/5]：正在等待数据库写入/提交，已 40 秒无进展；已成功 12000 行，
       批次 3 次，最近一批 28000 ms —— 若长时间不变，请检查目标库锁等待与资源，或点「停止」中断
    3) 每张表结束后输出耗时明细：
       [统计] 表名：成功 N 行，失败 M 行；批次 X 次，执行累计 A ms，提交累计 B ms，
       最近一批 C ms，读取+写入总耗时 T
  判断方法：
    - 看门狗提示“正在等待数据库写入/提交”+“最近一批”很大  → 瓶颈在数据库：
      查该表是否被其它会话锁住、是否有触发器/大量索引、redo 与磁盘 IO
    - 看门狗提示“正在读取 CSV 数据”                      → 瓶颈在客户端/网络：
      确认 CSV 是否在共享盘或网络盘上，可先复制到本机磁盘
    - 表进度显示“提交中...”                              → 数据已读完，正在等待数据库提交
    - 总进度右侧提示“数据暂无推进”                        → 同上，结合日志判断
    - 单批超过“写入超时秒数”（默认 120 秒）仍无响应        → 工具自动取消该批次：极速模式自动
      降级为标准写入（日志出现 [中断] / [降级]），标准模式该表标记失败并写明“写入超时/被中断”
  停止：点“停止”会立即中断正在挂起的数据库操作（无需等批次跑完）；已提交的数据不会回滚
  提速手段：数据量大时勾选“极速模式”；调大并发线程数与批量提交行数；
            大表临时把索引/约束置为不可用，导入后重建；
            并发写同一张大表若变慢，可把“单表最大分片数”调小（如 2）减少索引/ITL 争用

七、常见问题
  1) 双击 run.bat 窗口一闪而过 → 没找到 Java：安装 JDK 11+，或在本目录 jdk-path.txt 中
     填写 JDK 安装目录，或用 run.bat <JDK目录> 指定
  2) 提示“未找到数据库驱动” → 请使用本包内的 pdms-import-tool.jar
  3) 测试连接超时 → 检查网络、防火墙、数据库监听端口与账号权限
  4) 导入速度慢 → 勾选极速模式；调大并发线程数与批量提交行数；确认数据库磁盘/日志配置
  5) 提示文件被占用 → 关闭 Excel 等正在打开该 CSV 的程序
  6) 窗口显示不全 → 最大化窗口，或拖动中间分割条调整上下区域
  7) 极速模式日志出现“[降级]” → 正常兜底：该表改回标准 INSERT 写入，数据不会丢
  8) PG / 金仓提示 schema “xxx” 不存在 → 勾选“自动建表”后会自动 CREATE SCHEMA IF NOT EXISTS；
     若提示权限不足，请让 DBA 授权或在库中先手工建好 schema
  9) 金仓连接报找不到驱动 / 连不上 → 本包 jar 已内置 kingbase8 9.0.0 驱动；确认端口为
     54321、库名正确，且机器能访问数据库监听端口
 10) 金仓极速模式日志出现“[降级]” → 服务端不支持 COPY 写法时自动改标准 INSERT 写入，
     数据不会丢；想提速可先确认目标表无触发器、无大量索引
 11) MySQL 极速模式日志出现“[降级]” → 服务端未开启 local_infile（默认 OFF）：
     让 DBA 执行 SET GLOBAL local_infile=1，或改用标准模式（已靠 rewriteBatchedStatements 提速）
 12) MySQL 提示表不存在/库不存在 → 工具不会自动建库，请先让 DBA 建好库并授权，
     再勾选“自动建表”由工具建表

八、包内文件
  pdms-import-tool.jar   主程序（已内含 Oracle / PostgreSQL / 达梦 / 人大金仓 / MySQL 驱动，
                         并内置 PDMS 应用图标，启动后窗口标题栏 / 任务栏即显示该图标）
  run.bat                Windows 启动脚本
  run.sh                 macOS / Linux 启动脚本
  jdk-path.txt           JDK 路径配置文件（可选；没配 JAVA_HOME 时把 JDK 目录填在这里）
  README.md              完整功能说明（含参数细节、原理与打包成 exe / dmg 的方法）
  QUICKSTART.txt         本文件
  icons/                 应用图标素材
      pdms-16~1024.png   运行时窗口 / 任务栏图标（jar 内已内置一份）
      PDMS.icns          macOS .app / dmg 打包用图标
      PDMS.ico           Windows exe 打包用图标
